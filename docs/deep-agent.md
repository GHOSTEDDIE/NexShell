# DeepAgent 终端助手与迁移

## 运行结构

Eino 固定为 `v0.10.0-alpha.9`。`TurnLoop.PrepareAgent` 调用 `deep.New` 构建主助手，启用官方 `write_todos` 和 `task`，注册单层 `operations_worker` 子助手。子助手拥有独立上下文，顺序执行，通过同一套 SSH 服务和任务授权操作服务器。主助手与子助手的调用编号分属不同运行命名空间。

构建、中间件、工具入口、事件处理、验证和记忆存储分别位于 `internal/agent` 的独立模块。计划写入 SQLite，并在下一轮重新注入 Eino 会话状态。助手界面使用可折叠的计划、子任务及记忆记录；审批展示发起助手、目标服务器、终端资源及具体输入。

参考 einoclaw 固定提交 `f7b790f966487e7b9f8202c9d024f714b3030afb` 的多轮消息、中间件及审批组织方式：
https://github.com/YellowDusk04/einoclaw/blob/f7b790f966487e7b9f8202c9d024f714b3030afb/main.go
该提交本身使用 ChatModelAgent；本项目主助手使用官方 DeepAgent。保留原有 OpenAI 兼容和 Ollama 适配器，没有引入本机通用 Shell、外部消息机器人或云端追踪。

## 权限与验证

主机编号、连接身份和有效期是硬边界；操作和资源列表是自动执行白名单。白名单外的具体操作通过原审批入口确认，不能通过提示词或技能自行放行。Shell 和终端输入始终绑定具体请求。

子助手继承当前任务范围，不能再次委派，也不能做最终验证。主助手对每台服务器使用最新的成功只读执行结果验证；一个主机通过验证不会完成其他主机的任务。存在运行中或结果未知的执行时禁止继续变更。计划标记完成不能代替验证。

工具参数错误继续向模型提供可修正反馈。取消、审批中断、存储错误和未知结果保留原有控制流。终端输入成功只代表交付成功，仍需主助手独立读取并验证远端状态。

## Skills 与记忆

官方 Skills 中间件统一加载应用内置手册及 `<数据目录>/skills/*/SKILL.md`，名称保留 `builtin:`、`local:` 前缀。复用既有路径检查和文件大小约束。本版本的技能不能通过 frontmatter 自行改模型或创建额外 Agent；需要委派时由主助手调用 task。

官方 automemory 负责索引、主题选择和提取；SQLite 后端仅提供受限的 Markdown 读取、匹配、写入和编辑，不连接本机真实文件目录或 Shell。

- 主机事实使用 `host:<主机编号>` 命名空间，通用偏好使用 `preferences`。
- 只读取当前任务授权主机的记忆；主助手统一整理，子助手不重复保存。
- 主机提取输入来自最新验证证据的编号、操作、资源与短预期文本，不包含原始终端输出或完整文件。只有明确陈述的通用偏好进入偏好提取，包含主机身份或凭据关键词的内容不进入通用偏好。
- 使用官方同步提取模式，属于本轮运行生命周期；退出取消未完成提取。每条写入原子提交，写入前复核启用状态和删除代数。删除或关闭记忆后，在途提取不能重新写回。
- 普通写入使用读取版本检查，避免并发覆盖其他对话刚更新的内容；编辑在当前内容上做精确匹配。
- “助手 → 更多 → 管理记忆”提供查看、删除和关闭；提取或读取失败会显示记忆状态。

长期记忆只作为历史参考，不能授予权限，也不能证明当前服务器仍处于相同状态。提取需要额外模型调用；失败不会伪造保存成功。

## 旧任务兼容

新任务写入 `runtime_version=deep-v1`，检查点键使用 `deep-v1:<任务编号>`。旧二进制检查点保持原样，不由新 Agent 自动解码或执行。

旧任务直接发送或批准会提示需要升级恢复。通过“恢复任务”确认当前主机与原范围后，刷新身份快照和授权，保留历史并补齐未返回工具调用的中断说明，使用新的运行命名空间继续。旧批准不能批准新版请求。存在未知执行时仍需核实，不能自动重放。

配置、凭据、聊天历史和执行证据保持原存储位置。新结构使用现有 SQLite 文档表，不删除旧数据。该 Eino 版本是固定的预发布版本，后续升级需要复跑检查点、模型、工具及记忆兼容测试。

## 验证命令

```sh
go test -race -tags ci ./...
go vet -tags ci ./...
go test -race -tags integration ./tests/integration -v -count=1
NEXSHELL_REAL_MODEL=1 go test -race -tags integration ./tests/integration -run 'TestLinuxLab/deep_real_model' -v -count=1
```

真实模型测试仅在显式设置环境变量时运行，读取现有默认模型配置与系统凭据库中的模型密钥，使用新的回环 SSH 容器，不连接用户保存的业务服务器。审批只自动允许测试中固定的健康标记写入，其他请求让测试失败。测试日志不输出模型密钥。

## 本次验收结果（2026-09-10）

- 全项目 `go test -race -tags ci ./...` 通过；覆盖原有正确样本和新增的 DeepAgent 规划、Skills、子任务身份、审批恢复、多主机验证、旧检查点隔离、记忆禁用／删除／取消以及主题记忆读取。
- 完整隔离 Linux 测试通过：SSH、跳板、监控、文件校验与续传、ZMODEM、同一终端环境保留、子助手终端写入和主助手独立验证。
- 用户确认的默认 `ark-code-latest` 模型验收通过：规划 → 委派 → 精确终端输入审批 → 独立读取验证 → 主机记忆保存 → 新对话回忆健康标记。
- 初次真实模型测试出现流中断，未重放操作；随后修正自动白名单的提示歧义及主题记忆加载。中间失败日志与最终通过日志均保留，不能把中间失败当作通过证据。
- 窄助手面板中计划、子任务、执行及记忆块已生成并查看渲染图。其他系统的原生窗口交互仍需各平台实机验收。

最终通过的证据位于 `docs/evidence/deep-agent/unit-race.txt`、`linux-final.txt`、`real-model-complete.txt` 和 `vet.txt`。
