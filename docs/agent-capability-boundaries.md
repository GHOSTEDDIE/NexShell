# 助手能力边界与故障注入验证

本次直接测试应用执行链和本地模拟模型接口，确认并修复四类应用缺陷：不存在的工具导致工具节点终止；重复错误仅依赖提示词而循环至 100 次；模型接口短暂 503 即失败；空模型回复被误标为正常就绪。

## 修复行为

- 不存在的工具返回当前实际工具清单和能力限制。助手可以改用已有能力或解释无法执行，不会创建不存在的功能。
- 同一错误请求提供三次纠正反馈，继续重复由程序暂停；跨工具共用十二次纠错额度，避免换工具名绕过限制。正常操作仍受原有授权和验证机制控制。
- 新增“需要调整”状态，显示配置或任务调整原因。暂停后可继续聊天，未返回的工具调用补记为结果未确认，保留已完成结果。
- OpenAI 兼容接口在建立流式连接或生成响应时，对 429、500、502、503、504 以及连接超时最多尝试三次；401、403、400、404、422 不盲目重试。取消立即结束等待。
- 已经建立的流式响应不自动重放，避免重复文本或工具调用；空回复不再标为正常完成。无法继续时保留具体原因。

## 测试范围与证据

- 真实 Service 和工具节点：联网搜索、发邮件、本地文件读取、浏览器操作等不存在的工具；未知服务器；已授权服务器上的不支持操作；错误参数类型；重复失败；跨工具重复；暂停后续聊。
- 本地 HTTP 模型服务：503 后恢复、401/403、400/404、429/503 持续失败、输出中途断开、请求取消、空响应、损坏的流式 JSON、异常工具调用。
- 原有正常行为：OpenAI/Ollama 模型绑定、无服务器聊天、工具验证纠错、授权执行、未知结果不重放；界面可显示暂停原因并在继续后移除旧提示。
- `go test -race -tags ci ./...` 与 `go vet -tags ci ./...` 通过。
- `go test -race -tags integration ./tests/integration -v -count=1` 九项隔离 Linux 集成测试通过。

日志在 `docs/evidence/agent-boundaries/`，`before.txt` 和 `invalid-responses.txt` 保存修改前的失败，`boundaries.txt` 保存修复后的故障测试结果。使用模拟模型和本地测试服务器，没有发送真实邮件、读取用户本地业务文件、调用用户模型接口或修改用户远程服务器。测试结果证明上述场景已覆盖，不代表对所有外部服务和模型行为作零故障保证。
