# NexShell 卡顿问题修复（2026-09-09）

针对同日检查报告中的四项问题，已完成代码修复、回归验证和本地 macOS 应用打包。没有对真实业务服务器执行操作，也没有替换系统应用目录中的安装。本次没有取得原始整机卡顿时的采样，不能将历史卡顿归因于某个进程。

## 改动

1. **终端输入不再持锁等待网络。** 继续复用现有终端编码器、按键队列和发送协程，只替换编码器的输入传输管道。状态锁内的写入只操作内存，实际 SSH 写入在锁外；键盘、粘贴、鼠标与终端协议响应保持编码和顺序。网络发送失败后关闭输入管道，后续按键不会等待已退出的读者。为避免断网后输入无限积压，未发送输入最多保留 1 MiB，超过时清空待发输入并明确报告失败；此时应重新连接，不会自动重试未知交付结果。
2. **关闭工作区统一释放所有权。** 普通标签关闭和工具栏关闭复用同一入口，移除 App.workspaces 中的对象并清理终端注册。取消在界面线程立即生效，网络资源在后台关闭。还清空 Fyne 2.8 删除标签后留下的数组尾部引用。分屏连接完成时若工作区已关闭，则关闭该连接，不再把终端追加回已关闭工作区。
3. **任务历史改为后台增量读取。** 单个后台工作协程使用已有 Events(taskID, after) 读取新事件，界面线程只接收展示结果。没有变化时不重画；快速切换只保留最新选择，使用选择版本丢弃过期结果。保留运行中显示 execution_delta、结束后隐藏这些临时片段、失败显示原因和恢复任务的原有展示语义；切换任务时释放旧缓存。完成任务仍每秒查询轻量状态和新增事件，以便发现后续消息或恢复，但不再反复读取旧事件。
4. **回滚历史改为循环缓冲区。** 满一万行后覆盖最旧槽位，无需每次移动一万条行索引。调整容量时保持最近记录的时间顺序；清空历史时释放行引用。保留按行读取、搜索、备用屏幕和调整窗口大小的行为。

## 性能结果

相同机器（Apple M1 Pro）、同一合成单字符行基准：

| 历史上限 | 修复前插入耗时 | 修复后插入耗时 |
| --- | ---: | ---: |
| 1000 行 | 449.8 ns/次 | 60.37 ns/次 |
| 10000 行 | 4823 ns/次 | 58.86 ns/次 |

一万行场景的插入操作约快 82 倍，且不会随历史上限线性增长。该值仅衡量回滚缓冲区插入操作，不等于整个应用加速倍数。没有测量真实长时间连接的进程内存曲线，内存修复以所有权引用释放测试为依据。
