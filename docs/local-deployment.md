# 本地文件与部署包

助手现在可以查看本机目录、分段读取 UTF-8 文本、计算文件 SHA-256，并通过 SFTP 将本地部署包传到已授权服务器。主助手和运维子助手共用同一执行入口。

## 使用

直接在助手输入框添加本机文件，无需预先设置目录：

- 在 Finder 或 Windows 文件管理器复制文件，然后在对话框粘贴，支持多个文件。
- 在消息中输入或粘贴有效的本地文件路径，输入框会显示附件；含空格的路径可单独一行，或用引号、反引号包围。
- 点击“添加文件”选择文件，或把文件拖到对话输入区。原工作台文件区的拖入上传行为保持不变。
- 发送前可以移除附件，普通文字粘贴仍按原方式输入。

发送附件即允许当前对话读取所选文件，不自动开放其父目录或同目录其他文件。助手可读取文本进行对话、分析部署说明，或将二进制部署包直接传到服务器。文件在本地仍按原路径访问，文件移动后需要重新添加；此入口没有加入 PDF、Office 文档解析器。运维任务的可读目录设置仍可用于连续读取一个目录的高级场景。

例如：

> 将 /Users/me/releases/app.tar.gz 上传到已授权服务器的 /opt/releases/app.tar.gz，核对文件一致后，再按部署说明完成发布。

助手先检查部署包，再提交上传确认。确认窗口显示本地路径、服务器、远端路径、文件 SHA-256 和“仅新建／覆盖／续传”。默认仅新建，遇到同名文件会停止；覆盖和续传需绑定对应的具体请求。解压、运行部署脚本和重启服务继续遵循原有执行授权。

文本读取每段最多 4096 字节，返回 `next_offset` 以继续读取，保留 UTF-8 字符边界。目录列表最多 100 项或约 24 KB，超过时标注截断。二进制包只将路径、大小、校验值及传输结果交给模型，不把包内容编码进对话。读取文本的内容会进入所选模型上下文和本地执行记录。

## 实现与边界

- `local_files` 提供 `stat/list/read`，没有本机写入或通用 Shell。读取请求使用独立本机路径字段，不冒用服务器编号。
- 附件按精确规范路径、对话和授权编号保存，子助手继承同一范围；目录授权随任务保存，继承任务有效期和子任务范围。通过 `os.OpenRoot` 限制目录内的符号链接跳出范围；符号链接最终目标需使用实际路径。
- `operate upload_local` 绑定服务器身份、本机源路径、内容校验值、远端路径和上传方式。任何字段变化均使原批准失效。
- 上传先流式生成私有临时副本，核对源内容与批准的 SHA-256 一致后才接触远端文件。完成或失败后清理临时副本；需要本地磁盘容纳一份部署包，不将整包加载到内存。
- 数据传输复用工作台的上传、续传与完整校验服务。上传后使用独立 `file_hash` 读取远端文件并流式计算 SHA-256，作为主助手验证证据。远端文件校验需要再次通过 SFTP 读取全文件。
- 执行前后保留统一记录；断线且传输结果未确认时停止，不自动重放。同一调用编号复用原结果。应用退出时沿用原有任务取消和恢复流程。
- 上传目标已存在、源文件改变等在开始传输前即可确认的失败记为失败。传输启动后无法确认的错误保守标记为结果未知。
- 目录读取不等于服务器操作授权，本地内容和校验值也不能作为服务器已经部署成功的证明。

## 回归入口

```sh
go test -race -tags ci ./...
go test -race -tags integration ./tests/integration -v -count=1
# 明确选择已有默认模型后，使用隔离容器验证真实模型部署流程
NEXSHELL_REAL_MODEL=1 go test -race -tags integration ./tests/integration -run TestLinuxLab/local_package_real_model -v -count=1
```

记录位于 `docs/evidence/local-deployment/`。测试使用临时本地文件和仅监听回环地址的 SSH 容器，不读取本地业务文件，不连接已保存的业务服务器。
