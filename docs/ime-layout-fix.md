# 中文输入与设置导航对齐

## 修复

macOS 原有 GLFW 驱动先发送物理按键，再调用输入法，导致选字回车也被交给输入框或终端。原生文本协议还存在组合文字范围少一个字符、选择范围无效、提交后组合文字未清除、候选框坐标未转换到屏幕坐标的问题。

在保留版本和许可证的本地 GLFW 源码中修正这些行为：先处理输入法；开始、编辑或确认组合文字的按键不重复传给应用；显示尚未确认的文字；提交后清理组合状态。应用通过 Fyne 的 NativeWindow、CursorPosition 接口提供当前输入位置，覆盖普通输入框、助手输入框和终端。只在焦点、光标或窗口尺寸改变时更新原生锚点，关闭窗口时停止监听。

设置导航原来按不同文字宽度分别居中，图标起点相差 6.5。现在统一左侧图标列和文字起点，保留其他按钮的居中样式。

## 验证

- 实际设置窗口回归：修改前图标位置为 30.0/36.5，文字位置为 55.0/61.5；修改后对齐测试通过，亮色和暗色截图已检查。
- 独立隐藏窗口中的 Cocoa 输入协议测试：原始依赖将选字回车和正常回车共传递两次；补丁后只传递一次正常回车，提交的中文为“你好”，组合范围、选择范围、候选框坐标与提交清理均通过。
- 原生测试在 AppKit 主线程执行，不向用户窗口或系统事件队列发送测试键盘事件。
- `go test -race -tags ci ./...`、`go test -race ./tests/nativeime -count=1`、`go vet -tags ci ./...` 以及 macOS 原生构建通过。

证据在 `docs/evidence/ime-layout/`。本次自动化覆盖 Cocoa 原生协议；未将自动化键盘输入当作第三方输入法或所有输入法版本的完整验收。
